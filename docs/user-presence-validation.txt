確定したコード上の問題と修正
============================
1. application は lobby で取得した presence を保存していなかった。
   application が xr::user_presence を所有し、最後の実イベントの bool を
   optional で保持する。未知と既知 false を区別する。
   成功した xrBeginSession 後に、その session handle と capability を登録する。
   extension 非対応または supportsUserPresence=false では保存・送信しない。
   他の session の presence event は scene にも転送しない。
   セッション作成前、正常終了後、再開始、loss/exit、cleanup で古い値を消す。
   VISIBLE/FOCUSED やコントローラー入力から値を推定しない。

2. stream::create() は presence snapshot を送っていなかった。
   headset_info と session state の送信後、最新値が既知なら既存 control packet
   user_presence_changed を送る。false も送る。未知の場合は送らない。
   後続イベントと snapshot は同じ send_user_presence() を使う。
   時刻は既存の instance.now()、受信側は既存 offset_est の変換を使う。
   snapshot は送信時刻を持つ現在値であり、過去イベントの発生時刻ではない。

   application::loop() の poll_events() と lobby::render() 内の stream::create()
   は同じ application thread。async 接続処理は stream を作らない。
   create 中にイベント polling が割り込まないので、古い snapshot が新しい
   presence event の後に送られる経路は追加していない。
   create 後は既存 lobby::next_scene->on_xr_event() が後続イベントを転送する。
   scene activation 時の余分な再送・lock・protocol 変更は不要。
   切断すると stream は shutdown となり、lobby_gui が next_scene を解除する。
   再接続は stream 再作成を通り、同じ状態のままでも snapshot を再送する。

3. server start() は net_thread 起動後に resume_session() を呼び、最後に
   presence を false へ戻していた。受信済みの初期値を上書きする競合が可能。
   mnd_ipc_server 設定 → resume_session() 完了 → net_thread 起動に変更した。
   resume は音声・encoder 再開、descriptor/application list 送信、worker 起動、
   client states と presence 初期化を行う。packet の受信完了を待つ処理はない。
   client は snapshot 送信後に独立した network thread を開始して受信する。
   worker は時計同期要求等を送るが、presence packet を処理しない。
   初期化例外時には net_thread はまだ起動せず、通常の session 破棄が worker
   を停止する。再接続は既存どおり run_net() 自身が reset/handshake、resume、
   次の poll の順で実行する。handshake は headset_info まで受信するので、
   その後に送られる snapshot は resume 後に処理される。

   サーバーの既存の初期 false、および切断時 false の扱いは維持した。
   センサー非対応機器で HEAD_DETECT を公開する条件も変更していない。
   実際に競合が発生した実機ログはなく、VRChat 症状の解決は未確認。

参照した仕様
============

関連ソースから分かること
========================
ローカル Monado oxr_session.c は begin 時に HEAD_DETECT を update_inputs()
で更新し、初期 presence event を queue する。poll 時にも値の変化を通知する。
ipc_server_handler.c は block_inputs の対象に boolean input を含むため、
client に送る HEAD_DETECT が false になる可能性がある。
この挙動は WiVRn の保持値/packet と別の段階であり、今回変更していない。
xrizer src/input.rs は初めての既知値を changed とする修正を既に含んでいる。
手順書の一時的な tracing や workaround を復活させていない。
