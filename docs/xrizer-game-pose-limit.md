# xrizer のゲーム用頭部姿勢リミッター：後続実装の手引き

現時点ではコントローラーのリミッターのみ実装済みです。xrizer、Steam の
起動オプション、頭部姿勢の取得処理は変更していません。以下は後続実装の設計案です。

## 環境変数で渡す場合

候補名は `XRIZER_HMD_GAME_MAX_EXTRAPOLATION_MS`。これは新設する契約であり、
現在の xrizer が対応している環境変数ではありません。

- 未設定 / `-1`：現在の xrizer の動作を維持。
- `0`：ゲーム向け頭部姿勢を、フレームごとに取得した現在時刻までに制限。
- `1`〜`100`：現在時刻から指定 ms 先までに制限。
- それ以外：警告を一度出して既定動作を維持。整数として解析し、ns 変換前に検証。

WiVRn プロセスの `setenv()` は、既存の Steam や別のプロセスの環境には伝播しません。
Steam 起動オプションを変更しない条件なら、ゲームを起動する親プロセスに値を
設定してから起動する必要があります。実行中のゲームへの値の更新もできません。
この制約を許容する場合に環境変数方式を選んでください。

## 起動オプションを変更せずダッシュボードと連携する場合

既存のセッション D-Bus を使う案が適しています。新しい IPC を作らず、xrizer から
WiVRn の設定を読み出せます。環境変数による明示指定を優先し、未設定の場合のみ
D-Bus の値を使う構成にもできます。

- バス名：`io.github.wivrn.Server`
- オブジェクト：`/io/github/wivrn/Server`
- インターフェース：`io.github.wivrn.Server`
- プロパティ：`JsonConfiguration`（JSON 文字列）
- 読み出し：`org.freedesktop.DBus.Properties.Get`
- 設定キー候補：`hmd-game-max-extrapolation`（上記と同じ整数の契約）

上記キーとダッシュボード項目はまだ実装していません。追加時は既存の
`controller-max-extrapolation` の保存・復元・型検証を参考にしてください。
xrizer は接続時に一度取得し、`PropertiesChanged` で更新する方式にします。
描画スレッドでは D-Bus 通信をせず、検証済みの値をキャッシュしてください。
WiVRn が不在の場合や読み出し失敗時は通常動作を維持し、後から再接続できるようにします。
Flatpak / Steam のコンテナ内からセッションバスに接続できるかは別途検証が必要です。

## xrizer の変更箇所

ローカル実装の `src/compositor.rs` は `game_pose_time` と描画時刻を分離しています。
`GetLastPoses` / `GetLastPoseForTrackedDeviceIndex` のゲーム用出力について、
**HMD のみ**別の取得時刻を使います。通常の描画用出力、コントローラー、トラッカーは
既存の取得時刻を維持してください。

フレームごとに現在時刻 `now` を一度だけ取得し、有効時の HMD ゲーム用時刻を
次のように決めます。

```text
head_game_time = min(predicted_display_time, now + limit_ms * 1_000_000)
```

現在のローカル xrizer はゲーム用姿勢を全デバイスについて現在時刻で取得するため、
その時刻をさらにクランプするだけでは正の設定値が効きません。有効時だけ HMD の
ゲーム用出力を上記の時刻で取得し直すか、`src/input/devices.rs` にデバイス別時刻を
受け取るヘルパーを追加します。未設定時は現在の実装をそのまま維持します。

`WaitGetPoses` の同じフレームで何度取得しても `now` が変わらないようにし、
セッション再作成時にキャッシュをリセットします。現在時刻取得に必要な
`XR_KHR_convert_timespec_time` が使えない場合の扱いも既存コードに合わせます。

これは「現在時刻から何 ms 先の姿勢を要求するか」の制限です。WiVRn の
コントローラー設定のような「最新サンプルの生成時刻からの予測量」の制限とは
基準が異なります。OpenXR の通常の姿勢取得 API だけでは元サンプルの生成時刻を
xrizer に返せないため、同じ基準が必要なら専用のランタイム連携が必要です。
頭部のランタイム側 `get_tracked_pose` を一律に制限すると描画用の取得にも影響し得るため、
ゲーム用出力の選択は xrizer 側で行います。

## 検証項目

1. 未設定 / `-1` では現在の取得時刻・姿勢が変わらない。
2. `0` / `20` / `100` で、HMD ゲーム用時刻だけが上記の式に従う。
3. 描画用姿勢は常に元の描画時刻を使い、コントローラー / トラッカーに影響しない。
4. 一括取得と単一デバイス取得、ゲーム用出力のみの取得が一致する。
5. 同一フレームの再取得、フレーム更新、セッション再作成が正しく動く。
6. 無効値、時刻取得失敗、WiVRn 未起動、コンテナからの接続失敗時にも通常動作を保つ。
